# 可游玩的像素微缩场景

用户说要控制角色、在地图里走动或做成可游玩的场景时，加入 `walk` 配置。将小人当作场景中的比例参照。选择清楚的出生点和可走路线，让探索逐步揭示视线外的细节。保留原有旋转和缩放，使用「开始探索」切换到角色控制。

```json
"walk": {
  "spawn": [-2.5, 1.4],
  "avatar": "ash-keeper",
  "showAvatar": true,
  "facing": 0.48,
  "surfaces": ["path-stone-1"],
  "blockers": ["hut-walls", "rock-1"],
  "hazards": [[1.2, 2.4, 0.85]]
}
```

- `spawn` 为可站立地面的 XZ 坐标。 `blockers` 引用已生成形体的 ID，可为建筑、崖石、树干或其他实心障碍。 `hazards` 中每项为 `[x,z,半径]`，适合熔岩、破口等危险区块。
- `showAvatar: true` 让角色在观赏模式中也可见。可用 `facing` 指定初始弧度，0 面向 +Z。把出生点放在镜头前方无遮挡的路面，起步方向最好能直接到达第一处地标。
- `walk` 仅支持单层陆地地表，水域判定以 `water(x,z) > 0` 筛出水域外的地面，`<= 0` 的水域不可走。角色会避开地图边缘并受坡度限制。低矮铺石或平坦地台可用 `surfaces` 引用静止水平盒体的 ID，脚底跟随盒体顶面并在边缘过渡。悬空桥面无法直接踏上。做过桥效果时，用 `terrain.hills` 抬高局部陆地并确保路线位于水域范围外，或沿岸边布置路线。
- 桌面用 WASD 或方向键，触屏用画面上的方向键。拖动转动视角，移动方向跟随当前镜头。重置将角色送回出生点。
- `build.js --review` 生成的 `-front.png` 和 `-side.png` 静态审图不会渲染 `avatar`。用浏览器打开成品，点击「开始探索」，实测角色的位置与可见性。沿规划路线实际走一遍。检查出生位置、与地面接触、绕过障碍、边缘阻挡、视角改变时的移动方向、退出探索和触屏方向键。

## 为主题设计角色

- 给角色一个属于场景的身份，用头部轮廓、衣服色阶和一件有辨识度的道具表现。温泉看守用靛蓝棉袄、浅色头巾和木桶。灰钟关守夜人用灰色兜帽、暗红围巾和提灯。换主题时重选这三项，并让角色在默认镜头下能从地面和背景中辨认。
- `walk.avatar` 可填 `spring-keeper`、`ash-keeper` 或 `traveler`，也可直接写 `{"blocks":[...]}`。预设源文件在 `assets/avatars/`。自定义块形如 `{"part":"arm-right","from":[4,2,0],"to":[6,4,2],"color":"#c39966","top":"#e9dfc7","shade":"#a27147"}`。XZ 为 −12 至 12 的整数，Y 为 0 至 24，0 是地面。前方是 +Z。块按顺序叠放，后写的同部位像素覆盖前面的。
- `part` 为 `body`、`head`、`arm-left`、`arm-right`、`leg-left` 或 `leg-right`。把手持物的像素设成持物手臂的同一部位，步行动作会带着道具一起摆。角色最多使用 16 种颜色。压缩到几组主题色，并在地图缩略图上检查对比。
- 进探索后看正面和侧面，实际走完出生点至首个地标的路线，再尝试继续走进墙体或危险区。观察起步和收步、腿部摆动、提物手臂的幅度、脚底接触，以及远景能否看清剪影。
