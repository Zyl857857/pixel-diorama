# 3D 像素微缩艺术创作

## 从主题直接创作

主题足够明确时，直接选构图、光色和视角并出成品。一句话、单个物件或抽象意象都能作为输入。抽象主题先选一个能被看见的动作、地点或物件关系，再用它建立场景。用户给了明确的构图、配色、气氛或文件格式时，按其要求创作。

保持这个系列的画面语言：能从多个角度读取的三维体块，有限色阶构成的像素笔触，清楚的空间层次和受控的光色。让主题决定主角的剪影、空间组织、材质、色调和环境变化。根据内容选择微缩风景、剖面、室内布景或环绕式雕塑。具体做法与验收见 [造型与画面审查](references/art-direction.md)。

## 抽象艺术方向

用户要求抽象、象征或解构时，先保留能辨认主题的轮廓和部件关系，再选择碎裂、重组、重复或留白来改变形体。用骨龙配方观察如何把头骨、脊柱和翼骨组成仍可辨认的主体。具体做法见 [造型与画面审查](references/art-direction.md)。

## 动态场景

用户明确要动态、复苏或让主体动起来时，按主题自己设计一个能读懂的动作。让镜头在关键动作时让位，先做一个准备、发力和收势清楚的循环，再用次要部件补跟随动作。火、烟、布料和碎片按各自的支点、相位和受力节奏运动。用 [主体动画](references/motion.md) 编排动作并审片。

## 交互模式

默认使用作品观赏模式。用户明确希望控制小人、探索地图或实际游玩时，根据画面设计可走路线和与主题一致的可操控角色。延续已有角色时保留辨识特征。新角色按场景重选剪影、服装和道具。角色属于画面时，让它从第一眼就出现在出生点。按 [可游玩的像素微缩场景](references/explore.md) 加入玩法与验收。

## 生成与验收

1. 确立主视觉与一处能让人读出主题的细节。先确认定格画面成立，再加入适合主题的动势。编辑旧作品时，保留用户指定的形体、位置与画面特征。
2. 阅读 [配方字段](references/recipe.md)，为主题编写自己的配方。从 `assets/recipes/` 查阅字段用法和成品范例。用自带生成器构建。构建依赖 Node.js 18+，只使用标准库。
3. 在 Skill 根目录运行 `node scripts/build.js /absolute/scene.json /absolute/scene.html --review`。从其他目录运行时，将 `scripts/build.js` 换成实际的 Skill 内绝对路径，例如 `node "/absolute/skill/scripts/build.js" /absolute/scene.json /absolute/scene.html --review`。构建会生成作品 HTML、两角度渲染与布局检查文件，并在终端输出体检结果。检查主体、主题线索、阴影、接缝与空间感，再用缩略图检查远景是否清楚。根据渲染结果迭代。需要交互时，尽可能确认离线打开、视角控制和动态播放。
4. 默认交付一个可离线打开并旋转的 HTML 作品，在回复里放一张实渲染预览。若用户明确要静帧、动图、视频或其他格式，按指定格式优先交付。配方、源码、布局文件和工艺说明只在用户需要时提供。回复先呈现作品，用一两句说明主题如何体现在画面里。
